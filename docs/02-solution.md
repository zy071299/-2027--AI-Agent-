# 设计

Go CLI 每轮把问题、历史及已执行步骤发给模型，执行其选择的检索或原文读取，再把观察结果交给下一轮。结束动作可回答、追问或报告缺口。最多 12 步，整次运行限时 90 秒。引用从实际读取的文档构造并去重校验。

检索按合成资料中的主题词和同义词召回，返回所有匹配候选以便识别冲突。文档日期用于溯源。真实模型由提示词引导补查适用范围与优先级。离线 Mock 用规则复现典型路径，按原文是否相同判断合成冲突。

## 代码中的数据结构

以「报销期限多久」为例，模型先返回一个 `Action`，要求执行 `search`，参数是「报销期限」。Go 执行后把该动作和候选文档一起放进一个 `Step`。候选文档用 `Doc` 表示，此时只有 ID、版本日期和标签。

模型看到这个 `Step` 后选择 `read`，参数是 D01。Go 把 D01 的原文放进新 `Step`，后续读取 D02 时同理。若两份资料冲突，模型可再发出 `search` 查适用范围，最后用 `finish` 返回回答、状态、资料缺口和引用 ID。

`Result` 是 Go 输出给 CLI 用户的完整结果。Go 用 `finish` 提供的 ID 找到本轮读过的原文，组装 `Citations`，并把全部 `Step` 放进 `Trace`。因此 `Action.IDs` 只是模型选出的文档 ID，`Result.Citations` 才包含可核对的版本日期和原文。
